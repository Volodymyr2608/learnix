# ADR-005: Split Prisma Schema Folder

- **Status**: Accepted
- **Date**: 2025-11

## Context

A single `schema.prisma` file grows unwieldy as the model count increases. Related models (auth, course, enrollment, etc.) are better kept in separate files.

## Decision

Enable the Prisma `prismaSchemaFolder` preview feature and split models across `prisma/schema/*.prisma`:

```
prisma/schema/
├── auth.prisma           User, Session, Account, Verification (Role enum)
├── course.prisma         Course, CourseProgress, Section
├── courseGeneration.prisma  CourseGeneration, CourseGenerationMessage
├── enrollment.prisma     Enrollment (EnrollmentStatus enum)
├── instructor.prisma     InstructorProfile
├── lesson.prisma         Lesson, LessonProgress
├── quiz.prisma           Quiz, QuizAttempt
└── review.prisma         CourseReview
```

The root `prisma/schema.prisma` holds only the `datasource` and `generator` blocks.

## Consequences

**Positive**
- Each domain area is self-contained; changes to enrollment models don't touch auth models.
- Zod schemas auto-generated by `zod-prisma-types` go to `prisma/zod/index.ts` and are imported throughout the server layer.
- Generated Prisma client goes to `generated/prisma/` (outside `prisma/`) to avoid accidental commits of heavy generated files.

**Negative / Trade-offs**
- `prismaSchemaFolder` is a preview feature; it may have breaking changes in future Prisma versions.
- Cross-file relations (e.g., `Course` referencing `User` defined in `auth.prisma`) work fine but require awareness that models live in different files.
